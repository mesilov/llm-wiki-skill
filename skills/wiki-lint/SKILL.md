# Проверка wiki

Прочитай [контракт](../wiki-query/references/contract.md). По умолчанию
проверка не изменяет wiki, журнал и снимки источников. Прямой запрос исправить
проблемы или проверка уже разрешённой правки позволяют исправления в этой области.

1. Определи scope по запросу и схеме. Прочитай индекс и относящиеся страницы.
   Для большой wiki назови проверенную выборку; не объявляй её полной проверкой.
2. Если структура поддерживается, запусти `bin/wiki/lint --dry-run`;
   для источников — `bin/wiki/raw-lint [пути-единиц] --json`. При необходимости
   используй `status`, `find-orphans` и `affected`. Все эти команды только читают.
3. Отдельно проверь смысл: есть ли основания у важных утверждений, верно ли
   они пересказаны, различены ли факты и гипотезы, видны ли противоречия,
   согласованы ли определения и даты. Устаревший снимок не подтверждает «сейчас».
4. Проверь затронутые якоря и нужные внешние источники доступными средствами.
   Различай отсутствующий локальный файл, недоступный из среды ресурс и
   непроверенную актуальность. Не дописывай фиктивные источники ради проверки.
5. Сверь глоссарий по [правилам](../wiki-query/references/glossary.md):
   нужные для понимания понятия без определения, конфликтующие определения
   и названия, смешение определения с применением, порядок записей. Проверь,
   что значимые изменения знания в границах проверки отражены в журнале.
   Неподдержанное определение или запись журнала не придумывай: сообщи замечание.
6. В разрешённом режиме исправления устрани подтверждённые проблемы, сохраняя
   первичные материалы, затем повтори соответствующие проверки. У CLI нет
   `--fix`: осмысленные исправления выполняет агент.

Пример: lint вернул 0, но вывод не имеет основания. Отчёт должен назвать
смысловой пробел; ноль означает только отсутствие обнаруженных механических ошибок.

В отчёте укажи проблему, файл и влияние, предлагаемое либо выполненное исправление.
Раздели механические результаты, смысловые замечания и непроверенные части.
