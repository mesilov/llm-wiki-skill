# LLM Wiki Skills

Четыре навыка для локальной wiki: источники, связанные знания и ответы с основаниями.
Набор адаптирован из `pdlc-llm-wiki4sdlc-skill`. Включает CLI, установщик,
updater и полный SimpleEn-RU. Существующие wiki не мигрируются автоматически.

| Навык | Назначение |
| --- | --- |
| [wiki-query](skills/wiki-query/SKILL.md) | Ответ по знаниям без записи |
| [wiki-ingest](skills/wiki-ingest/SKILL.md) | Сохранение источника и включение в знания |
| [wiki-update](skills/wiki-update/SKILL.md) | Уточнение, объединение и разделение страниц |
| [wiki-lint](skills/wiki-lint/SKILL.md) | Проверка структуры и смысла; исправления по запросу |

Факты, гипотезы и решения различаются. Источники сохраняют происхождение и дату;
противоречия остаются видимыми. Навыки используют [общий контракт](skills/wiki-query/references/contract.md).
Устанавливайте комплект целиком: простое копирование одного SKILL.md недостаточно.

## Установка

Нужен Python 3.10+. Из checkout набора, в существующий каталог проекта:

```bash
python3 scripts/install.py /path/to/project --init-wiki --dry-run
python3 scripts/install.py /path/to/project --init-wiki
```

По умолчанию навыки копируются в `.agents/skills/` для Codex, инструменты —
в `bin/wiki/`. `--agent claude` дополнительно создаёт относительные symlinks
в `.claude/skills/`. `--agent opencode` использует тот же `.agents/skills/`.
Меню выбора нет. Для существующего корпуса уберите `--init-wiki`.

Установщик проверяет конфликты до копирования; отличающиеся файлы не заменяет.
Одинаковые файлы пропускает. При системном сбое копирования возможна частичная
установка без отката. Повторный запуск пропустит полностью скопированные файлы,
но незавершённый файл вызовет конфликт. Сверьте его с исходником и вручную
восстановите либо удалите только подтверждённый незавершённый файл перед повтором.
AGENTS.md и CI проекта не меняются.
Набор не следует устанавливать в checkout его исходников.

Новый корпус содержит только:

```text
raw/README.md
knowledge/SCHEMA.md
knowledge/index.md
```

Тематические страницы добавляются по содержанию. Схема — короткое описание
соглашений wiki. Профиль `wiki.config.json`, PDLC-представления и OpenSpec
не используются. Для нестандартной существующей структуры агент следует её
схеме; CLI поддерживает только соседние `raw/` и `knowledge/`.

## Проверки

Из целевого проекта:

```bash
bin/wiki/lint --dry-run
bin/wiki/status --json
bin/wiki/find-orphans
bin/wiki/affected 'понятие или путь'
```

| Команда | Проверяет или показывает |
| --- | --- |
| `lint` | Локальные Markdown-ссылки, выход путей за границы, наличие индекса и страницы без входящих ссылок |
| `status` | Число Markdown-страниц, ошибок ссылок и страниц без входящих ссылок |
| `find-orphans` | Страницы знаний без входящих ссылок; индекс, схема, README, глоссарий и журнал в корне исключены |
| `affected` | Кандидаты по прямым ссылкам, пути, имени файла или фразе |
| `raw-lint` | Формат единицы источника, YAML, происхождение и дату получения |

Все пять команд только читают. Поддерживаются `--json` и `--project PATH`.
Без явного корня CLI ищет `knowledge/` вверх от cwd, не переходя границу
вложенного Git checkout или установленного комплекта. Для корпуса в `docs/wiki/`
передайте `--project docs/wiki`. В `affected` путь отсчитывается от корня корпуса;
явные пути `raw-lint` — от cwd. CLI не читает `wiki.config.json`.

`lint` и `raw-lint`: код 0 — нет обнаруженных ошибок, 1 — найдены ошибки,
2 — ошибка вызова или выполнения. Предупреждения не меняют код 0.
`status`, `find-orphans`, `affected`: 0 — отчёт получен, 2 — ошибка выполнения.
Пустой результат `affected` не доказывает отсутствие смыслового влияния.

Разбор ссылок унаследован от донора: обычные и reference-style Markdown-ссылки,
исключение примеров в блоках кода. Это не полный CommonMark-парсер; сложные
вложенные конструкции, HTML-ссылки и wiki-links могут требовать ручной проверки.
Якоря, внешние URL, истинность и свежесть утверждений проверяет агент.
У CLI нет `--fix`: правки по результатам проверки выполняются осмысленно в
рамках запроса. Нулевой код не подтверждает готовность всей wiki.

### Источники

Для нового корпуса: `raw/YYYY-MM-DD-slug/README.md`, оригинальные файлы рядом.
В YAML обязательны `source` и `retrieved`. См. [формат и пример](skills/wiki-query/references/raw.md).
Это упрощённый локальный формат, без контракта OKF донора.

Только для `raw-lint` нужен PyYAML. Установите его в Python-окружение проекта:

```bash
python3 -m pip install -r bin/wiki/requirements.txt
bin/wiki/raw-lint --json
bin/wiki/raw-lint raw/2026-11-11-interview --json
```

Без путей команда проверяет единицы непосредственно внутри raw/.
Старая или иная структура требует своих проверок; автоматической конвертации нет.
Оригинальные вложения не разбираются и не выполняются. YAML загружается через
подкласс SafeLoader с запретом повторных ключей; см. [документацию PyYAML](https://pyyaml.org/wiki/PyYAMLDocumentation).

## Обновление инструментов

```bash
bin/wiki/update --check --json
bin/wiki/update
bin/wiki/update --yes
```

Проверка обновлений выполняется по запросу, без обязательного сетевого обращения
при каждом запуске навыка. Источник — `mesilov/llm-wiki-skill` на GitHub.
Канал `main` используется по умолчанию; `--channel release` выбирает стабильный
GitHub Release. Если релиза нет, fallback на main не происходит.
Доступность опубликованного комплекта требуется для сетевого обновления;
локальная установка не требует публикации.

`--check` только читает manifest и GitHub, без скачивания полного комплекта.
Обычный запуск предлагает обновление в терминале. `--yes` применяет его без
диалога, сохраняя защиту локальных изменений и удалений. `--force` разрешает
их замену/восстановление и повторную установку той же revision. Не используйте
force для обычного автоматического подтверждения. `--json` допустим с `--check`.

Updater скачивает архив точного commit SHA, проверяет состав и пути, не запускает
код из архива. SHA закрепляет версию, но не является цифровой подписью.
Manifest содержит revision, SHA-256 и права управляемых файлов. Локальные
изменения содержания, прав и удаления блокируют обычное обновление.
Старые управляемые файлы удаляются только по manifest; неизвестные файлы,
корпус, AGENTS.md и настройки проекта сохраняются. Manifest другого репозитория
отклоняется: обновление не является миграцией установленного PDLC-комплекта.

Прежние заменяемые файлы и manifest сохраняются в `.wiki-kit-backups/<id>/`.
При обрабатываемой ошибке записи updater пытается восстановить исходное состояние
и сообщает backup. Прерывание процесса или питания требует ручной проверки;
автоматического восстановления после перезапуска и блокировки параллельных
запусков нет. Перед обновлением завершите другие записи в файлы комплекта.

Коды updater: 0 — версия совпадает или обновление выполнено; 1 — обновление
доступно, но не выполнено; 2 — ошибка сети, архива, manifest или конфликт.
Проверка версии не является проверкой целостности локальных файлов.

## Техническое письмо

Полный SimpleEn-RU включён в `wiki-query/references/utr-source/`: каталог
правил, чек-лист, примеры, области применения и эвристический линтер.
Исходные файлы и их лицензия сохранены побайтово. [Обвязка](skills/wiki-query/references/writing.md)
задаёт границы: стиль не меняет факты, цитаты, исходники, язык задачи и область записи.

## Проверка разработки

```bash
python3 -m unittest discover -s tests -t .
git diff --check
```

Тесты установки и updater используют временные проекты. HTTP updater подменён
детерминированными ответами; тесты не подтверждают наличие удалённого релиза.
Проверка навыков включает отдельные практические сценарии и проверку структуры.
См. [происхождение](docs/provenance.md) и [отчёт проверок](docs/validation.md).
